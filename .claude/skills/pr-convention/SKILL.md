# Pull Request 규약 (iamhoonse-world)

> github-workflow 플러그인의 기본 규약 대신 이 문서를 따라요.

## 제목

커밋 규약(commit-message)과 같은 형식이에요.

```
<type>[(scope)]: <한국어 요약>
```

- 브랜치의 커밋이 여러 개면 PR 전체를 대표하는 type/scope 를 골라요.

## 본문

`.github/pull_request_template.md` 의 항목을 **빠짐없이** 채워요.

| 섹션          | 작성 기준                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| 🔗 관련 이슈  | 머지 시 닫을 이슈는 `Closes #번호`, 참고만 하는 이슈는 `Refs #번호`                                           |
| 📝 작업 내용  | 무엇을, 왜 바꿨는지. 커밋 단위로 정리하면 좋아요                                                              |
| ✨ 개선 효과  | 이 변경으로 좋아지는 점                                                                                       |
| 🎯 영향 범위  | 변경된 앱/패키지, 영향 받는 기능, **위험도**(🟢/🟡/🔴 중 하나), **하위 호환성**                              |
| ✅ 검증 방법  | **검증한 것과 검증하지 못한 것을 구분**. 해당하는 체크박스만 체크하고, 확인 절차를 번호로 적어요              |
| 📸 스크린샷   | 화면 변경이 있으면 첨부, 없으면 "해당 없음"                                                                   |
| 💬 리뷰어에게 | 고민한 지점, 후속 작업, 그리고 **함께 수정해야 하는 곳**이 있으면 반드시 적어요                               |

- 기본 브랜치에 있어야 동작하는 변경(GitHub Actions, 이슈 템플릿 등)은 ✅ 검증 방법에 **머지 후 확인 절차**를 적어요.
- 리뷰 중 추가 변경이 생기면 PR 본문도 함께 갱신해요.
- 템플릿의 HTML 주석(`<!-- -->`)은 지워도 돼요.

## 라벨

- 연결된 이슈의 **작업 유형 라벨**(`enhancement`, `refactor`, `infra`, `project-setting`, `documentation`)을 PR 에도 붙여요.
- 이슈가 없거나 작업 유형이 `기타`면 라벨을 붙이지 않아요.
- `task` 라벨은 이슈 전용이라 PR 에는 붙이지 않아요.
